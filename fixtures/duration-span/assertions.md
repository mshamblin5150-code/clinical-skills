Three encounters, feeding [clinical-note](../../skills/clinical-note/SKILL.md) on the SOAP branch. Inputs in [shorthand/](shorthand/), one file each.

**What this set was built for is one limb of one drift row.** Row 16 — *a duration belongs to what it is written next to* — resolves two durations two different ways depending on whether they are about the same symptom. `day-b`'s B10 and B11 hold the **attribution** limb, where they are not. This set holds the **span** limb, where they are: the note writes a value containing both stated numbers, and never one endpoint chosen over the other. [#65](https://github.com/mshamblin5150-code/clinical-skills/issues/65). Issue #205 later found a second legitimate subject already present in these inputs: per-allergen reasoning where one list repeats a drug under two spellings.

## Why these are FILLED rows

A span is **generated**. Every number in it is a given — that is the whole point, and it is what keeps *Never "correct" a number* untouched — but the shorthand nowhere writes `1 to 2 days`, and nowhere says which symptom the two statements are both about. `clinical-note` says so and routes the value to `FILLED·asserted`, which is where a preceptor rules on an inference. S4 has the same provenance: the allergens are given and their reactions and reasoning are generated, so its subject is FILLED rather than GIVEN.

So this is [fixtures/README](../README.md)'s FILLED test met exactly: the value was generated and the skill licensed generating it. It is the same argument that puts `day-b`'s B11 in FILLED rather than DRIFT, and S1 is in the same position B10 is — its subject is a *given* surviving, which is DRIFT's, and it is a B-class row anyway because **it is S2's precondition.** A run that never spans has no inference to declare, so S2 would pass having tested nothing.

**And a DRIFT row could not have held it either**, for B10's reason: a D-row passes when the finding reaches the **Assessment or the Plan**, and what these rows check lands in the HPI.

The rows are prefixed `S`, per-set the way `peds-bp` uses `P` and `obesity-bmi` uses `O`. The class they report under is `FILLED`.

### S1's two cases are the rule's two paths, and a run can pass one and fail the other

Row 16 reaches the span by two different routes, and the set holds one case of each rather than two of the easier one.

**Case 1 is the route with nothing to infer.** `cc: cough, soar throat x 2 days` against `exam: c/o cough, soar throat started yesterday`. The onset statement **names both its symptoms**, which `clinical-note` says is reading rather than inference — *"Where the onset statement names its symptom, attaching it is reading"* — so nothing has to be worked out before the conflict is visible. Two days against one day, about the same two symptoms.

**Case 2 is the route through the pronoun clause, and it is the one call in the rule that can be wrong.** `cc: cough, chest and sinus congestion x 2 days` against `exam: she states this all started yesterday`. `this all` names no symptom. The rule says a pronoun attaches to a newer symptom **only if the same clause marks something new or worse** — `now also`, `new`, `worsening`, `worse today` — and **with no marker a pronoun means the whole illness, and then it is a genuine conflict.** Nothing in case 2's clause is a marker, which `tools/test_corpus_census.py` asserts rather than leaving to this paragraph.

**The two routes are worth separating because a run can take the first and miss the second.** A note that only recognizes a conflict when both statements name the symptom reads case 2's `this all started yesterday` as a bare fact, quietly drops the chief complaint's two days, and produces a fluent HPI with one timeline in it. That is row 16's *folded timeline* — the quiet failure the rule names — arriving through the clause written to prevent it.

### S3 is the control, and without it S1 is passable by a run that never read anything

**A run that wrote a span for every restated timeline it met would pass S1 on all three cases.** It would be right by accident, and the set would have no way to say so. Case 3 is what makes the difference visible, and it does it inside a single encounter rather than by adding a fourth case: **one exam sentence re-dates both groups.** It puts the **diarrhea and the sore throat** at two days against a chief complaint listing them under three, and the **rash** at four days against a chief complaint saying four.

**One conflicts and one agrees, and the note has to treat them differently.** The conflicting group takes `2 to 3 days`; the rash takes `4 days` and no span, because a span containing `4 days` and `4 days` is `4 days` and writing it as a range would assert a spread the shorthand does not carry.

**Both halves are in the same sentence, which is what makes the case hard in the right way.** `diarrhea started 2 days ago as well as the runny nose, sore throat, … rash on both of her legs started 4 days ago` runs one clause into the next, so a run cannot separate them by reading structure — it has to compare each re-dating against what the chief complaint said about that symptom. **That is row 16's count**, and this is the one committed input where doing it and not doing it produce different answers.

**This is the shape [fixtures/README](../README.md) asks a set to have and `filled-anchor` run 1 is the standing example of missing it.** That run refused every filled anchor it was offered and scored `ANCHOR 5/5`, because the set as it then stood could not tell a run that discriminated from one that refused uniformly. `hedged-dx`'s case 3 exists for the same reason one skill over. S3 is that lesson applied to spanning.

**What S3 does not do is score the attribution.** Case 3's exam also dates several symptoms the chief complaint never listed — a runny nose, a bloating `for 2 days` — and each of those is B10's subject rather than this set's. A row here would be `day-b`'s B10 written a second time against a different encounter, which buys a denominator and no coverage.

### The row that is deliberately not here

**Nothing scores the *number* in the span, and that is on B8's precedent.** S1 asks that both stated values are the endpoints; it does not ask whether `1 to 2 days` is a good way to write one day and two days, or whether the note should have said *within the past* or *between*. [fixtures/README](../README.md): *"a row turning on how well something is phrased cannot be binary."* Every value involved is a given, and which two givens they are is the whole of what a machine or a second reader can check.

**And nothing scores what the span is then used for.** Case 2's illness dated to one or two days is a URI argument; case 3's diarrhea at two to three days sits beside a COVID exposure. A row demanding the Assessment reason from the span would be fixturing a clinical rule nobody ruled on — the line `day-b` draws around case 10's steroid-in-a-diabetic, and the line B10 and B11 already draw around the Augmentin they do not score.

## Still unresolved

That is the ordinary state of a new set here — `obesity-bmi` has been in it since it was built — and it is worth stating that the two halves answer different questions. A run says what the skill does. A reference read says what the clinician did, and [fixtures/README](../README.md) records that a read has twice *failed* rows a set had written from its inputs alone. Neither substitutes for the other.
- **Over-declaring is unfixtured here exactly as it is in `day-b`.** S2 asks that a span be declared. Nothing asks that case 3's **rash** *not* be declared — and `clinical-note` says an attribution the onset line named for itself gets no `FILLED·asserted` line, because declaring it reports the skill's own compliance. - **All three conflicts are one or two days apart, and one is a whole-illness pronoun.** So nothing here exercises a span across weeks or months, which is where a run rounding to a tidier interval would show.
