# Replacement property v1 workflow selection

The existing diagnostic workflow selects this versioned combined route.
`--replacement-property-v1` is mutually exclusive with calibration-only mode.
The original strict first-control route and the unselected calibration-only route
retain their behavior. Implementation/review is not publication, native execution,
merge, or production adoption.

## Predicate and private binding

`run_property_control(root, runtime)` owns a fresh invocation. It accepts no prior
receipt, witness, calibration result, or authorization token. Fresh calibration
must complete both same-path attempts, mandatory held poststate, verified released
namespace transition, source-name absence, and verified closure before any live
owner is started. Its private result binds the actual API instance, fresh root,
unchanged deadline, actual integer held error, and authenticated fixture volume.
The public calibration wrapper still returns only its detached finite witness.
The shared invocation parent chain is sampled before calibration, after its
completion, again on live callback admission after pair preparation, and after
mandatory live poststate. A renamed/recreated context refuses even on one volume.

The live callback is local to this invocation and binds the exact pair/runtime,
original authenticated receipt authority handle, and that handle's lifetime.
It can be consumed once. The existing second before-mark callback does not
repeat denials; it retains the original store's authority and disposition checks.
This prevents accidental historical/public-state reuse, not malicious code
executing inside Python's process.

The live replacement must return false and its immediately read error must be
5 or 32. Live 5 additionally requires this invocation's held calibration error 5.
Live 32 permits held calibration 5 or 32. Other/missing/noninteger calibration
errors refuse before a live owner. Every accepted live error requires mandatory
exact poststate verification; no legacy supplemental-proof exception suppression
is used. Public witness fields never authorize anything.

The live proof verifies the same continuously held authenticated authority,
fresh source/destination names, full volume and FileId, safe coherent snapshots,
exact bytes, distinct source identity, and sampled stable parents. All temporary
observers and writers close before replacement; all poststate observers close
before DeleteFile or later capture marking. Missing evidence, mismatches,
unstable reads, uncertain closure, call/getter exceptions, and proof failures
refuse. The private calibration success record is produced only on successful
completion of the actual proof and closure sequence.

CreateFileW write and DELETE-open denials still require error 32. The subsequent
DeleteFile denial still requires false/error32. Original receipt lifetime,
same-object READ|DELETE capture disposal, owned process cleanup, and source
authentication remain unchanged. Failures retain evidence, do not retry or
reset the fixture, and never fall back to another route. A known primary error
survives a secondary writer-close error; uncertain cleanup remains unknown.

## Bounds and observation

The complete resource relation is executable in
`compact-replacement-property-v1-accounting.json` and its public CLI/encoded
receipt test. Every field has a mutation discriminator. Calibration's fresh
fixture allocation is deducted from the existing aggregate receipt allowance;
the live replacement source was already included in the first-control baseline.
No extra capture or native owner beyond the original first-control population
is introduced. No deadline is reset or enlarged after calibration. Conservative
storage ceilings, source command envelope, and public output limits remain.
Admission is not a guarantee that combined work finishes: deadline exhaustion
refuses instead of extending the job.

The property terminal and retained receipt have a distinct versioned schema and
explicitly state production qualification is false. The finite detached witness
contains only calibration status/call categories and live call/error/poststate
categories. Missing or malformed observations are unknown. Full private evidence
and failures remain retained; public output contains no paths, IDs, raw bytes,
or exception text. The existing terminal serialization limit remains enforced.

## Claim ceiling

This predicate numerically broadens the old error32-only condition and adds
mandatory evidence. It is not described as simply stricter. Calibration matches
process/API policy, flags, share policy, and volume, not ACL or filter equivalence.
Sampled unchanged poststate does not prove continuous namespace presence, exclude
transient changes or ABA, establish the sole cause of refusal, erase an old object,
or qualify production. Only the successful calibration rename comparison permits
ChangeTime to differ; live held-denial poststate remains exact.

Portable tests use real synthetic namespace changes and open descriptors. They
are not Windows qualification. The existing workflow changes only its selected
route and step label. Its branch, single job, first-attempt guard, time limit,
and source-authentication setup remain unchanged.
