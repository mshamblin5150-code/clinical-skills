# Fixed first-control probe

This is a separately reviewed source-only route, not a subset flag or a patched
population of the original driver. Publication and native execution remain held.
No local Windows execution, application import, benchmark, upload or historical
cleanup is part of preparation. The old full-native workflow is disabled with
branch and tag exclusions; the other held workflows remain unchanged. The only
active push workflow in this packet is `synthetic compact first control`, on the
existing `diagnostic/2013-parallel-proof-20261020` branch. Reruns and other event,
workflow, platform, interpreter and branch identities refuse. There is no dispatch,
retry, fallback, full-packet continuation, or upload-artifact step.

## Order and proof boundary

The driver retains first-status, complete raw Git-object inventory, clean/raw
workfile verification, original core-pin authentication, and final verification.
New tracked route files are included in that full inventory, not exempted from it.
The source session and original native operations and guards are unchanged. The driver
creates its own runtime subclass solely to refuse a second or nested owner before
launch. It invokes exactly `snapshot_share_receipt_success` with its original
native permissions, sharing, guards, receipt chain and proof predicates.

After initial source authentication and conservative time admission, a deterministic
exception-emission self-control executes before the native control. It raises an
owned synthetic exception through the same `control_boundary` as a genuine failure,
checks exact exception preservation and finite witness projection, and sends the
result through the same `emit_terminal`, `q.emit`, and route-wide `PublicOutput`
transport used by the genuine final summary. It emits a separate event explicitly
labeled `injected_exception_only`, expected failure, inconclusive, and not native
qualification. Its witness describes a prepared fixture with no returned store
outcome, not invented disposal evidence. Private observation and exception sentinels
are excluded. This control creates no owner, file, native API, receipt or disposal.
Failed projection or transport stops before the real control, without retry.

A successful self-control establishes only portable observation/transport behavior.
It cannot qualify native failure emission, a returned store result, or native
disposal. A successful genuine first control does not exercise its own failure
branch. The two results remain separate in the final record. Portable tests also
inject failure in the actual first-control path to check the existing finite store
outcome and reconstruction witnesses through the new route. Those injected APIs
are explicitly not real Windows evidence.

The terminal helper bounds its actual JSON representation plus newline to 4 KiB.
Witnesses retain the original 2 KiB cap. Both emitted self-control output and final
summary share the existing 4 MiB aggregate public allowance; the self-control does
not consume the final terminal reserve. A failed/missing terminal or failed cleanup
is inconclusive. The primary failure survives cleanup or publication failure.

### Replacement-call observation

The existing replacement denial has two finite observational fields, without
changing its proof predicate: only a false return and sharing error 32 pass.
`replacement_call` is `not_returned`, `entered`, `returned_false`, `returned_true`,
`call_raised`, or `error_read_raised`. `entered` means the Python invocation
boundary, not proven Windows syscall entry. `not_returned` is initialized
observation, not proof that no call was attempted. `error_read_raised` means a
false result was observed but its last-error query raised.

Only `returned_false` carries `replacement_error`: `sharing_32`, `access_5`, or
`other`. All other states carry null. Missing, malformed, or inconsistent pairs
project to two nulls, never negative execution proof. No raw error number, path,
handle, or exception text is exposed. Observation writes are best effort and
cannot replace the original exception; a lost update proves no execution fact.
The original single replacement call and immediate false-only last-error query
remain, with no query on success, changed native rights, retry, or fallback.

Portable injected return/error and exception cases distinguish these observations,
not actual Windows behavior. In particular the nonzero-return fake does not
replace any pathname and cannot prove the physical effects of native success.
