# A writing pass stages patient text in a scratch root, enters the run by copy and rename, and a hook refuses heredoc writes there

**Measured at:** b73661b6b7f75e26ed95095c965c1ac322d6217b

[#1416](https://github.com/mshamblin5150-code/clinical-skills/issues/1416) was filed from the
after-action review of a batch-shift run. Note passes wrote their notes through Bash
heredocs, which collapsed backslashes and ended commands early, leaving partial files. One pass
brief asked for estimated visit times to be recorded as gaps. A shift-wide sweep and grader run
started while passes were still writing, read truncated notes as finished, and overwrote a repair.
A later comment recorded a fourth heredoc recurrence, in an orchestrator writing AAR ticket
bodies, and asked for a mechanical refusal.
[#1476](https://github.com/mshamblin5150-code/clinical-skills/issues/1476), filed from a
later shift, recorded the recovery route itself as a defect: passes staged patient text
through the system temp directory and collided in a shared temp folder. Grilled 2026-10-03 against
`main`, where the freshness gate read `FRESH`; the clinician ruled every point below in that
session. **Nothing is built here; this is the record the build reads.**

## Measured before ruling

### The proposed recovery route is #1476's defect

#1416's diff told a pass running in a worktree to write into its session scratchpad and `cp` the
file into `scratch/runs/shift-<date>/`, because the Write tool refuses paths in the owning
checkout. The session scratchpad is under `AppData\Local\Temp\claude\`, the system temp directory.
That directory carries no gitignore rule, no `phi_scan` path layer, and no cleanup. Writing the
diff into the skill would have turned #1476's item 1 into the instruction.

### Standing rule 6 already forbids two of the three defects

[AGENTS.md](../../AGENTS.md) standing rule 6 already gives every writing pass a run-unique
location no sibling can read or write, which forbids #1476's shared-folder collision. It already
says the per-file and whole-set checks run over the completed state after every writer has
finished, which forbids #1416's sweep during active writes. It already makes every private path
temporary and removes it after the checks. The recorded run broke a rule that exists; it did
not fall into a gap.

### The visit-time rule already lives in clinical-note

`skills/clinical-note/SKILL.md` lists start and end times among the values generated by design and
declared rather than reported missing, and states that estimated is a property of the value, not
the absence of one. `tools/block_scan.py` row F2 fails a note whose `GAPS` entry opens on a start or
end time. The recorded brief contradicted the skill its pass ran.

## Ruling 1. A writing pass stages its files inside a scratch root, never the system temp directory

Each writing pass gets its own folder at `scratch/sessions/<key>/<pass-label>/` in the scratch
root of the checkout it runs in, created by the orchestrator before launch. The pass writes its
files there with the Write and Edit tools, never a shell heredoc, then places each finished file in
the run with one copy and reads the destination back before reporting complete. Patient text never
passes through the system temp directory or the session scratchpad. Rule 6's cleanup removes the
staging folder after the checks complete.

## Ruling 2. The write route is a standing rule 6 paragraph, stated in every brief

The route in ruling 1 is a new paragraph in `AGENTS.md` standing rule 6, beside the browser-tab
paragraph and on its terms: the orchestrating context states it in every brief whose pass writes a
file, and no skill file copies it. It binds the orchestrator's own file writes too, since the fourth
recorded heredoc instance was an orchestrator writing AAR bodies.

## Ruling 3. Entering the run by copy and rename is the completion signal

A pass copies its finished note into the run under a temporary name and renames it to
`note-N.md`, so a partially copied file never appears under its real name. Batch-shift step 6
begins only when the run holds `note-1.md` through `note-N.md` for every encounter the clinician
confirmed at step 4; a missing number means a pass is still writing. A correction after a failed
check repeats the same copy and rename, so the run copy only ever changes as a whole file. Step 6
cites rule 6's existing sentence that checks run after every writer has finished rather than gaining
a paragraph of its own. No marker file is introduced and no grader changes.

## Ruling 4. Batch-shift step 5 points at clinical-note for visit times

One sentence in step 5 says the pass brief carries nothing that contradicts `clinical-note`, and
names the recorded instance: a brief never asks for a visit time to be recorded as missing, because
`clinical-note` estimates every start and end time. It cites that rule rather than restating its
reasons or the F2 row.

## Ruling 5. A hook refuses a heredoc that writes into scratch or output

A `PreToolUse` hook refuses a Bash heredoc that writes a file under `scratch/` or `output/` in any
checkout. It reads a heredoc redirected into a file there with `>`, `>>` or `tee`, and a
`python - <<` body that opens or writes a file whose literal path resolves there. The refusal names
the Write tool and the standing rule 6 route as the remedy. The hook reads commands through the
shared command reader and registers for the tools that reader models. Its limits object declares
the Python-body read a floor, a target the hook cannot resolve as unread, and PowerShell here-strings
as unread, so a clean pass is never read as "no heredoc wrote there."

## Ruling 6. #1416 carries the whole build

The hook is built under #1416 with the prose it enforces, so its remedy text cannot name a paragraph
that does not exist. #1416 also takes #1476's items 1 and 2, which ruling 1 answers. #1476 narrows to
its items 3 and 4, the agreement-reader brief.

## What the build must not change

A heredoc that writes no file under `scratch/` or `output/` is untouched, including the
commit-message form `git commit -m "$(cat <<'EOF' ... EOF)"` and a short in-place splice of a
tracked file. No roll-up grader gains a refusal. The `clinical-note` visit-time rule and F2 keep
their wording.

## Rejected options

**Stage through the session scratchpad, as #1416's diff wrote it.** Patient text passes through the
system temp directory, which is #1476's recorded defect.

**Have a Python script write into the run's private folder, as #1476 proposed.** The note text has to
sit in the script as a string literal, which reintroduces the escaping hazard the no-heredoc rule
removes.

**Require batch-shift to run in the owning checkout.** The skill cannot enforce how a session is
launched, and a session that opens in a worktree breaks the route again.

**State the write route in batch-shift alone, or in both places.** The fourth recurrence was outside
batch-shift, and the tab rule set the precedent that a brief rule lives in rule 6 with no copies.

**A per-pass marker file graded by every roll-up grader.** It changes graders other skills use and
guards against a partial write that ruling 1's single copy already prevents.

**Restate the visit-time rule in batch-shift, or make "a brief never overrides its skill" a new
cross-skill rule.** The first is a second copy of a `clinical-note` rule; the second binds every
fan-out on one recorded instance.

**Refuse every heredoc that writes any file, or every heredoc.** The first refuses permitted splices
and needs carve-outs; the second breaks the commit-message form every session uses.

**File the hook as its own ticket.** It enforces this ticket's rule and quotes its route, so it is
entangled with the ticket rather than inherited by it.
