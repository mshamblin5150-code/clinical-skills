# A ruling cohort promotes when every member is scored, whether it passed or failed

`fixtures/README.md` has said since [#29](https://github.com/mshamblin5150-code/clinical-skills/issues/29) that a counted row is promotable when it is *counted for want of a run* rather than for turning on phrasing. It never said what happens when the run arrives. **The exit rule was missing, and the consequence was not that promotion was slow — it was that the thing being decided kept changing shape.**

[#79](https://github.com/mshamblin5150-code/clinical-skills/issues/79) was filed over five rows in two sets. By the time it was answered it covered **ten rows across four sets**: #94 appended one on 2026-08-16 and #96 appended four the same day, both citing #29's *promoted together or not at all* as the reason their rows belonged in the same decision. Two sessions, neither of them deciding policy, doubled the group in a day. **On that trajectory the group grows and the decision recedes**, and every row in it stays a defect nobody has to fix.

This ADR fixes the boundary and the trigger. **A ruling cohort** is the assertions across one or more fixtures that express one clinician ruling; **a valid score** is a pass or a fail read from output produced while the asserted rule was in force; a cohort promotes when every member holds one.

## Considered options

**Promote only a cohort that passes.** Rejected, and it is the option the repo had been taking by default. Of #29's five, three fail — day-b's R1, R2 and R4 — so this rule promotes nothing here, and it would promote nothing anywhere for a structural reason rather than a local one: **a row is likeliest to get its first score on the run that fails it**, because a run that fails a row is a run somebody grades carefully. It also gets the causation backwards. Whether a bar can be set is a question about the row; whether the skill clears it is a question about the skill. Tying the first to the second means the skill's defects decide which rules get enforced, and an enforced failing row is exactly the arrangement that stops a known defect being carried forward silently — which `hedged-dx`'s `NAMING` class already does, retrospectively scored to two fails and a pass.

**Wait for a complete re-run of every set involved.** Rejected on cost and on what it would buy. #29's cohort spans two sets; #96's spans four. A separated run is twelve generating passes plus seven graders per set, and #79's own history is what a wait like that costs: `fixtures/day-b/assertions.md` records the denominator moving three times inside one ticket, *"rows are cheap to write and a run costs twelve generations plus seven graders."* What it would buy is nothing the row needs — **a row is scored by the cases it names**, and running the other nine cases of a set to score a row that names three is evidence about the set rather than about the row. So *targeted scoring* is admitted as sufficient for a cohort, and kept separate from a complete run's fraction so the two are never confused.

**Renumber the counted row into the binary class.** Rejected. It reads as the tidy answer — one row, one identifier, in the class its bar belongs to — and it destroys the record. `REPORTED 0/1` and `REPORTED 1/4` were written against rows that no longer exist under that arrangement, so every historical scorecard becomes a fraction over a denominator nobody can reconstruct, and every citation to `R2` in four files points at a row that has become `B20`. **Append-never-insert already binds rows across a reorganization**, and it binds harder across a class boundary than inside one. The cost accepted instead is that the same subject is named twice — once as history, once as an enforced row — and the mark on the historical row is what keeps the second copy out of the first one's denominator.

**Wait until the group stops growing.** Rejected, and it is the only option that is strictly worse than the status quo, because it *is* the status quo with a name. The group grew from five to ten in one day precisely because *promoted together or not at all* had no boundary: a new ruling covering the same subject read as joining the existing decision. **A cohort is closed at promotion**, and a later ruling opens a follow-on cohort with its own boundary — [#200](https://github.com/mshamblin5150-code/clinical-skills/issues/200) for #94's single row and [#201](https://github.com/mshamblin5150-code/clinical-skills/issues/201) for #96's four. Closing is what makes *together or not at all* a rule about a knowable set rather than about whatever has accumulated.

## Decision

`fixtures/README.md` gains a *Promotion* section stating the lifecycle, and `CONTEXT.md` gains the three terms it is written in. #29's cohort — day-b R1 through R4 and day-a R14 — is promoted as the worked instance: each historical row keeps its identifier and its verdict, is marked promoted, names its successor and leaves every later `REPORTED` denominator; each successor is appended to a binary class and carries its predecessor's verdict as its first score. day-b gains **B19 through B22** at `FAIL`, `FAIL`, `PASS`, `FAIL`; day-a opens a `FILLED` class for **A1** at `PASS`.

**The verdicts are carried forward, not re-measured.** They are day-b run 3's `REPORTED 1/4` and day-a run 2's four-for-four on R14, both scored against output produced after #29 landed — which is what makes them valid rather than convenient. No note was generated for this, and `clinical-note` is untouched: **changing the skill to make a promoted row pass would be the one move that voids the whole arrangement**, since the point of enforcing a failing row is that the failure stays visible until somebody fixes it on purpose.

## Consequences

**Three of day-b's binary rows now fail, and the set failed already.** B19, B20 and B22 record real misses — ungrounded social detail, an incomplete slot enumeration with hedges in it, and a dependency line that enumerates wrongly — on a set whose bar was already failing on B6. What changes is that these are now failures rather than observations, so the next run's scorecard cannot read clean while they stand.

**day-a gains a binary class it did not have**, which changes what *running the set* reports there: `FILLED n/n` joins `DRIFT` and `REPORTED` on its scorecard. Its one member passes, so its bar is unmoved today.

**The `REPORTED` denominators shrink in both sets**, and the historical ones do not move. day-b's future `REPORTED` covers R5, R6 and R7; day-a's covers R1 through R13 and R15. A reader comparing a new scorecard to an old one is comparing different denominators on purpose, and the promoted rows are marked so that is visible from the row rather than only from a changelog.

**A promoted row's verdict is exactly as good as the run it was carried from.** Nothing here re-separates the generating pass from the grading pass — that separation happened at run time and is inherited, not re-earned. The limit is the same one every retrospective score in this repo carries, and it is worth stating rather than leaving to be discovered: `hedged-dx`'s `NAMING` rows were scored this way, and #153 later reclassified the *instrument* that settled one of them without any verdict moving at all.
